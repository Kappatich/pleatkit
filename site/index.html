02 / mechanism

How it works

  1. Mark the zones.

    In vite.config.ts you list the files the agent may rewrite and the files it may read. Everything else stays closed: the agent sees only its type declarations.

  2. The user asks.

    They open the chat, point at a panel and type what they want. A small model sorts the request first. Backend work goes to your admin queue and no code gets written.

  3. The agent drafts and the code is checked.

    The agent cannot finish until the whole zone compiles. The browser compiles it again and swaps the panel in without a reload, in about 100 ms from compile to paint once the code arrives.

  4. The edit stays, and can be undone.

    It is saved as that user's snapshot with undo, history and reset. Your admin sees the request, the diff and the agent's tool log, and can roll it back.

readonlyapi.ts, ui/ · read, never written

One config line decides what is hatched. Writes outside the hatch are refused by the tool itself, not by a prompt.

03 / not this

What it is not

A component catalog.

With json-render, A2UI or CopilotKit, an agent builds screens from blocks you defined in advance. That is safe, but it stops at what you predicted. In morphkit the agent writes new code inside files you allowed, behind compile checks, zones and undo. If a catalog covers your users' requests, use a catalog.

An app builder.

Lovable and Bolt change an app for its creator, and then you deploy. morphkit changes the running app for one end user. Your repository and your release stay as they are.

Retool or Plasmic.

Those help your team build screens. morphkit lets the people who use a screen adjust it, inside the React app you already have.

A backend tool.

It edits frontend panels. A request like "store a new field" is routed to you. A free-form meta field on your entities turns many of those into frontend-only edits.

04 / install

Install in five steps

Any Vite + React project. Full guide and options in the README.

  1. Install the packages

    pnpm add @morphkit/runtime @morphkit/ui
pnpm add -D @morphkit/vite-plugin @morphkit/agent

  2. Mark the zones in the Vite plugin

    morphkit({
  zones: {
    dynamic: ['src/dynamic/**'],                            // the agent rewrites these
    readonly: ['src/readonly/**', 'src/components/ui/**'], // the agent reads these
  },
  externals: ['react', 'react/jsx-runtime', '@/components/ui/*', '@/lib/utils', '@/readonly/*'],
  css: 'tailwind',
})
// and proxy the agent: server: { proxy: { '/agent': 'http://localhost:8789' } }

  3. Move changeable panels into src/dynamic/

    Each file default-exports a component; render it through <Dynamic> instead of importing it.

    <Dynamic id="customer-card" props={{ customer }} />

  4. Wrap the app and add the chat

    <MorphkitProvider config={config} store={new LocalStore()} userId={user.id}>
  <App />
  <MorphkitChat agentUrl="/agent" />
</MorphkitProvider>

  5. Run the agent server with your key

    MORPHKIT_API_KEY=<your key> npx morphkit-agent   # http://localhost:8789/agent

06 / faq

Questions a senior engineer asks

Can a generated edit attack other users or leak data?

An edit runs only in the browser of the user who asked for it, so a bad edit can reach only that user. The agent can write only to dynamic files, and imports are limited to a list you control. With connect-src 'self' in your CSP, edit code cannot call other hosts. Edits shared between users can run in a sandboxed iframe that has no access to the page, cookies or storage. Static rules for generated code (no eval, no requests to other hosts, imports only from your list) run at every check, and an edit that breaks one is refused.

Where does the model key live?

In the environment of your agent server and nowhere else. The browser talks to your /agent endpoint and never sees the key. You bring your own key.

What CSP do I need?

script-src 'self' blob: 'wasm-unsafe-eval' and worker-src blob:. You don't need 'unsafe-inline' for scripts. We test this exact policy in e2e. A CSP without blob: is not supported yet.

What if the agent breaks the UI?

Code that doesn't compile never reaches the user. The agent must pass the check before it can finish, and the browser checks again before committing. If a panel compiles but crashes while rendering, the error stays inside that panel and the panel rolls back by itself after about 10 seconds. Undo and reset are one click.

What does one edit cost, and can it run away?

A small model sorts each request first, so a backend request costs one cheap call. A full edit is $0.03 to $0.07 on Sonnet 5.5 (estimate, not yet measured). Each edit stops at 12 model calls, 90 seconds or 8,000 visible output tokens. You can change all three limits.

Am I locked in?

The library is MIT. A snapshot is a plain copy of your dynamic files. With the browser store, morphkit runs with no server of ours. Remove it and your panels go back to being your original files. When you ship a release, users with edits get three choices: keep them, have the agent port them, or reset.

Can I self-host?

Yes for the library and agent server, today. The hosted store and dashboard are the paid Cloud product. A self-hosted store comes with the B2B plan.

Which models and stacks?

By default, Claude Sonnet 5.5 writes edits and Haiku 5.5 sorts requests. OpenAI, OpenRouter and any OpenAI-compatible endpoint also work. The stack today is Vite, React and TypeScript. Tailwind 4 classes work in edits, including arbitrary values. Next.js is next.
