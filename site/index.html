Your users change your UI by asking.

morphkit puts an AI agent inside your web app. It rewrites only the panels you mark as dynamic, the change is compiled in the user's browser and swapped in without a reload, and every user keeps a personal version with commit, undo and an admin who sees every diff.

Catalog-based generative UI (json-render, A2UI)

The model fills a JSON spec from components you built in advance. Safe, but it can only rearrange what already exists: no generated code, so a request your catalog did not foresee cannot be met.

morphkit

The agent writes actual React and Tailwind in a fenced zone of your code. Nothing applies until the whole zone compiles; every edit is a snapshot you can undo; it changes only the screen of the user who asked.

How it works

You decide what the agent may touch, with globs in the Vite plugin. Everything else stays yours.

dynamic

The agent rewrites these

Panels mounted as <Dynamic id="customer-card">. Each user gets their own copy of this zone, compiled in their browser.

readonly

The agent reads these

Your typed API client, formatters, UI kit. It imports them; writes are refused and logged as violations.

core

The agent sees types only

Everything else: routing, auth, data. The agent gets .d.ts declarations, never the source.

Install in five steps

Any Vite + React project. Full guide and options in the README.

  1. Install the packages

    pnpm add @morphkit/runtime @morphkit/ui
pnpm add -D @morphkit/vite-plugin @morphkit/agent

  2. Mark the zones in the Vite plugin

    morphkit({
  zones: {
    dynamic: ['src/dynamic/**'],                            // the agent rewrites these
    readonly: ['src/readonly/**', 'src/components/ui/**'], // the agent reads these
  },
  externals: ['react', 'react/jsx-runtime', '@/components/ui/*', '@/lib/utils', '@/readonly/*'],
  css: 'tailwind',
})
// and proxy the agent: server: { proxy: { '/agent': 'http://localhost:8789' } }

  3. Move changeable panels into src/dynamic/

    Each file default-exports a component; render it through <Dynamic> instead of importing it.

    <Dynamic id="customer-card" props={{ customer }} />

  4. Wrap the app and add the chat

    <MorphkitProvider config={config} store={new LocalStore()} userId={user.id}>
  <App />
  <MorphkitChat agentUrl="/agent" />
</MorphkitProvider>

  5. Run the agent server with your key

    MORPHKIT_API_KEY=<your key> npx morphkit-agent   # http://localhost:8789/agent

    Without a key it runs the scripted provider, so you can try the whole flow offline.

FAQ

Is it bring-your-own-key?

Yes. The agent runs on your server (@morphkit/agent) and reads the key from its environment only. The browser never sees it. You pay your model provider directly; morphkit does not resell tokens.

Which models does it use?

By default Claude: Sonnet 5.5 writes the code with adaptive thinking, Haiku 5.5 classifies the request first so backend work goes to the admin without calling the big model. Any OpenAI-compatible API (OpenAI, OpenRouter) works through MORPHKIT_PROVIDER=openai-compatible. The harness is pluggable.

What does an edit cost?

We estimate a few cents per edit on Sonnet 5.5 with prompt caching, but we have not measured it on a live model yet; the script that measures it is in the repo (pnpm agent:live). The visible output is capped at 8k tokens per edit.

Does it work with a strict Content Security Policy?

Yes, without 'unsafe-inline' for scripts: script-src 'self' blob: 'wasm-unsafe-eval'; worker-src blob:; style-src 'self' 'unsafe-inline'. Edits load as blob: modules, the compiler is WebAssembly. Sandboxed panels load their host script as a separate file, which needs Access-Control-Allow-Origin: *. The demo serves itself under exactly this policy in the test suite. A CSP without blob: is not supported yet.

Is it safe to let a model write code in my app?

The agent can only write files in the dynamic zone; writes elsewhere are refused and logged. Code must compile before it applies, twice: on the agent server and in the browser. A panel that crashes while rendering is rolled back automatically.

An edit runs in the browser of the user who asked and only changes their own version, so it can only affect that user. Panels can also run in a sandboxed iframe with an opaque origin, with no access to the page, cookies or storage. Admins see every request and diff, can roll any edit back, and can turn on review mode.

Not done yet: production authentication for the store-server (the demo trusts headers), and type checking of edits.

Which stacks are supported?

React 19 with Vite 6 and Tailwind 4 (Tailwind is compiled in the browser for the classes an edit uses). Next.js and webpack are not supported yet.

What happens to user edits when I ship a new release?

Their snapshot is marked stale. The user can reset to the new version or ask the agent to carry their customizations over to it.
